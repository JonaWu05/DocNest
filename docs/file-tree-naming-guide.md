# 檔案樹顯示名稱與真實檔名規則

本文說明 DocNest 檔案樹目前的顯示邏輯、真實檔名限制、`index.md` 的用途，以及使用時容易誤會的地方。

## 核心觀念

DocNest 將「真實路徑」和「畫面顯示名稱」分開處理。

- 真實路徑用於儲存、連結、權限判斷、同步與 API 操作。
- 顯示名稱用於左側檔案樹與目前開啟檔案的 UI 呈現。
- 真實檔名不建議承載中文標題；中文標題應寫在 Markdown 內容裡。

例如磁碟上的真實結構是：

```text
projects/
  docnest/
    index.md
    file-tree.md
```

其中 `projects/docnest/index.md` 的內容是：

```md
# DocNest 專案
```

而 `projects/docnest/file-tree.md` 的內容是：

```md
# 檔案樹顯示名稱與真實檔名規則
```

左側檔案樹會顯示為：

```text
projects
  DocNest 專案
    檔案樹顯示名稱與真實檔名規則
```

也就是說，`projects/docnest` 仍然是真實資料夾路徑，但畫面上會用 `index.md` 的 H1 顯示成 `DocNest 專案`；`file-tree.md` 仍然是真實檔名，但畫面上會用該文件的 H1 顯示成 `檔案樹顯示名稱與真實檔名規則`。

## 真實檔名限制

透過系統新增、改名、上傳或掃描進檔案樹的真實名稱，只允許下列字元：

```text
A-Z a-z 0-9 - _ .
```

也就是說，真實檔名與資料夾名稱不允許中文、空白、emoji、斜線、冒號或其他特殊符號。

允許：

```text
notes.md
project-docnest
meeting_2026-07-05.md
assets/screenshots/home-page.png
```

不允許：

```text
讀書筆記.md
project docnest
會議記錄/0705.md
final?.md
```

另外，以下名稱也會被視為不合法或不進入主檔案樹：

- Windows 保留裝置名，例如 `con.md`、`nul`、`lpt1.txt`
- 結尾是 `.` 的名稱，例如 `note.`
- 以 `.` 開頭的隱藏項目，例如 `.trash`、`.secret.md`
- 系統自動管理的 `assets` 附件目錄

如果磁碟上已經存在不合法真實名稱，掃描檔案樹時會略過，不會顯示在左側檔案樹。

## 檔案顯示名稱

一般 `.md` / `.txt` 檔案的顯示名稱依序取：

1. 第一個 Markdown H1，例如 `# 我的文件標題`
2. 若沒有 H1，取第一行非空文字的前 20 個字
3. 若內容也沒有可用文字，取真實檔名並去掉副檔名

因此 H1 可以和真實檔名完全不同。

範例：

```text
真實檔名：auth-design.md
內容第一個 H1：# 權限與登入設計
檔案樹顯示：權限與登入設計
```

這是預期行為。真實檔名負責穩定路徑，H1 負責人類閱讀。

## 資料夾顯示名稱與 index.md

資料夾本身沒有 Markdown 內容，因此資料夾顯示名稱來自該資料夾底下的 `index.md`。

範例：

```text
projects/docnest/index.md
```

內容：

```md
# DocNest 專案

這裡可以寫資料夾首頁內容。
```

左側檔案樹會把 `projects/docnest` 顯示為：

```text
DocNest 專案
```

如果資料夾底下沒有 `index.md`，或 `index.md` 沒有 H1 / 可用標題，則資料夾會顯示真實資料夾名稱。

## index.md 是否永遠隱藏？

不是。

左側檔案樹預設隱藏 `index.md`，因為它主要被視為「資料夾首頁」與「資料夾顯示名稱來源」。

使用者可以在左側檔案樹搜尋框下方打開 `index.md` 顯示開關。打開後，`index.md` 會出現在檔案樹中，並可像一般文件一樣開啟、編輯、重新命名或刪除。

為了避免混淆，`index.md` 自身在檔案樹中顯示完整檔名 `index.md`，而不是顯示它的 H1。它的 H1 會歸屬給資料夾顯示名稱。

## index.md 除了第一個 H1，其他內容會不會被任何地方顯示？

不會自動顯示在左側檔案樹。

檔案樹只使用 `index.md` 的標題來決定資料夾顯示名稱。`index.md` 的其他內容只有在使用者開啟該文件時，才會在主內容區正常顯示。

換句話說：

- `index.md` 的 H1：會用來命名資料夾
- `index.md` 的正文：不會出現在左側檔案樹，也不會自動展開成摘要

## 是否需要固定入口文，例如 overview.md 或 readme.md？

目前系統唯一有特殊語意的資料夾入口文是：

```text
index.md
```

不需要再建立 `overview.md` 或 `readme.md` 作為資料夾入口。

如果你想寫資料夾首頁、說明、導覽或索引，建議直接使用該資料夾底下的 `index.md`。

其他檔案名稱，例如 `overview.md`、`readme.md`、`summary.md`，都會被視為一般文件，不會影響資料夾顯示名稱，也不會預設隱藏。

## 檔案排序邏輯

目前檔案樹排序規則固定在後端建立快取時完成：

1. 資料夾在前
2. 檔案在後
3. 同類型依真實名稱做大小寫不敏感排序

排序依據是真實檔名 / 資料夾名，不是：

- 建立時間
- 修改時間
- Markdown H1
- 前端自訂排序
- 顯示名稱

範例：

```text
alpha-folder/
project-folder/
about.md
z-note.md
```

即使 `z-note.md` 的 H1 是 `# A 開頭標題`，它仍然會依真實檔名排在 `about.md` 後面。

## 保留檔名與特殊檔名

目前有幾類特殊名稱：

### index.md

`index.md` 是資料夾首頁與資料夾顯示名稱來源。它預設在檔案樹中隱藏，但可透過 UI 開關顯示。

### .trash

`.trash` 是資源回收筒使用的內部目錄。因為它以 `.` 開頭，會被檔案樹掃描略過，不會顯示。

### assets

`assets` 是附件庫目錄。主檔案樹會略過它，附件會在附件管理功能中處理。

### 以 . 開頭的名稱

所有以 `.` 開頭的檔案或資料夾都被視為隱藏項目，檔案樹不顯示。

### Windows 保留名稱

以下名稱不可作為真實檔名或資料夾名，即使加上副檔名也不允許：

```text
con prn aux nul
com1 com2 com3 com4 com5 com6 com7 com8 com9
lpt1 lpt2 lpt3 lpt4 lpt5 lpt6 lpt7 lpt8 lpt9
```

## 隱藏規則總整理

主檔案樹不顯示：

- 以 `.` 開頭的項目，例如 `.trash`
- `assets` 目錄
- 不合法真實名稱，例如中文檔名、含空白檔名、含特殊符號檔名
- 非文件副檔名，例如 `.exe`、`.png`、`.pdf`
- 預設狀態下的 `index.md`

其中 `index.md` 是唯一可以由使用者透過 UI 開關顯示的隱藏項目。

其他被略過的項目不會因為打開 `index.md` 開關而出現。

## 常見問題

### index.md 顯示開關打開後，為什麼顯示 index.md，而不是它的 H1？

因為 `index.md` 的 H1 已經被用作資料夾顯示名稱。

如果 `index.md` 自身也顯示同一個 H1，檔案樹會出現兩個看起來相同的項目：

```text
DocNest 專案
  DocNest 專案
```

這會讓使用者不容易分辨哪個是資料夾、哪個是首頁文件。因此 `index.md` 節點顯示完整真實檔名 `index.md`。

### H1 改了，檔案樹會立刻更新嗎？

檔案樹標題是在建立 `CachedTree()` 時讀取並快取。系統內新增、改名、刪除會讓檔案樹快取失效。

如果只是修改既有文件內容中的 H1，檔案樹可能會等快取 TTL 到期或重新載入後才更新。這是為了避免每次顯示檔案樹都重新讀取所有文件內容。

### 真實檔名可以和 H1 完全無關嗎？

可以。

建議真實檔名使用穩定、短、英文 slug；H1 使用真正要給人看的中文標題。

```text
真實檔名：sync-conflict.md
H1：# 共編衝突處理策略
```

### 資料夾一定要有 index.md 嗎？

不一定。

沒有 `index.md` 時，資料夾會顯示真實資料夾名稱。只有當你希望資料夾顯示中文名稱、說明性名稱或首頁內容時，才需要新增 `index.md`。
